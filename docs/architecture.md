# Architecture

## Initial design

**Rust** owns the Aurora importer and encounter state. The importer turns a character save and its content definitions into data the app can use. The combat logic owns how damage, concentration, companion changes, and timed effects update an encounter. Keep this logic testable without opening the desktop window.

**Tauri** provides the Windows window, native file dialogs, and a bridge from the UI to Rust. A Svelte click handler calls a named Rust command through `invoke()`. The command calls the core and returns the updated session view or an error through local inter-process communication.

**Svelte and TypeScript** render the combat sheet and handle interactions such as opening a description or changing the layout. A change to encounter state, such as spending a scroll, goes through a Rust command.

Aurora is the source of character build data. The tracker owns the session and layout, so re-import can update available options without resetting the fight. Companion behavior comes from imported definitions and editable cards. The Artillerist’s cannon exercises the same companion system as a ranger’s pet or a summon.

## Aurora content import

The Rust importer reads a UTF-8 character save and local content XML files. It resolves equipment, spells, build selections, and companions by the exact Aurora content ID. Each saved reference retains its ID and label with an optional definition. A missing definition leaves the reference available for display or later correction. File read errors, malformed XML, and duplicate definitions within one file fail the import.

Callers pass content files in Aurora load order. A later file can replace a definition with the same ID, and targeted `append` entries contribute rules and supports in file order. Each resolved definition records its source file and published version when present. It keeps the definition's description markup, sheet text, setters, rule attributes, and other content as data.

The import catalog follows exact IDs named by grants, ID-based selections, and embedded descriptions. This makes related options such as the Artillerist's cannon variants available even when the save names only the parent feature. The catalog records unavailable targets and visits each ID once. Saved selections retain their own lists, and rule data retains conditions such as levels and support expressions for later evaluation by the app.

## Re-importing a character

A Rust character session keeps the Aurora snapshot and its source paths alongside tracker-owned encounter state, layout, and pins. Re-import reads the same save path so a character rename leaves the session attached. The session loads the entire new snapshot before applying it. A failed read or parse leaves the previous snapshot, sources, and tracker state available for retry. Callers can supply an updated list of content files in Aurora load order.

Pins for saved equipment, spells, build elements, and companions follow the exact Aurora content ID in the corresponding list. Pins for linked options follow IDs in the reachable definition catalog. An unresolved ID still qualifies while the refreshed save or catalog references it. Re-import removes pins whose targets disappear and returns them in their previous order. It preserves the order of the remaining pins, tracker-owned pins, and the encounter and layout values.

## Combat sheet

Rust projects the imported character into a combat sheet that can be rendered independently of encounter updates. It uses Aurora's action labels and spell casting times for grouping. Saved attacks and weapons appear under Action. The importer reads weapon and feature references from Aurora's calculated build summary as well as the direct selections. Clearly stated item activations, charge costs, and fixed save DCs can be read from descriptions when equivalent metadata is absent. Options with another casting time or unidentified activation remain visible in a separate section.

The projection uses saved spellcasting attack modifiers and save DCs for spells that call for them. A scroll uses its linked spell's casting time, range, and description with the scroll's own costs and roll values. A generated scroll ID can omit the source prefix, so it resolves only when the supplied library has exactly one matching spell ID suffix. Features recorded in the save and unconditional feature grants can provide combat options. Descriptions with level-specific action or usage metadata show that level alongside the option.

The current browser preview is a standalone HTML file generated by the Rust CLI. It keeps navigation to the three groups available while scrolling and uses independent inline disclosures for full descriptions. Description markup is limited to a safe set of formatting tags. The combat sheet data can also feed the planned Svelte view.

## Key stats and character layout

The importer uses saved ability scores, equipped armor, and the active build summary to calculate supported HP, AC, speed, and save baselines. Hit points use the class hit die for the first level and the saved average-HP option for later levels. Movement and other bonuses use supported Aurora stat rules. The preview exposes unavailable values and allows local overrides for values that need a correction, such as rolled HP or conditional defenses. The full sheet reads identity, background, personality, and lore from the save.

The standalone preview stores stat overrides, ordered pins, and section order and visibility in browser storage. It namespaces preferences by a stable key derived from the canonical save path. Regenerating the same preview for a renamed character at that path keeps their preferences. Pins use content IDs, saved attack identifiers, and spellcasting source IDs where available. The preview keeps key stats and the full-sheet link visible independently of hidden combat sections. Desktop session preferences remain owned by the Rust session.

## Consumable use

Aurora supplies inventory amounts and instance identifiers. The tracker records units used against the item ID and its instance identifier. Entries without an identifier share a stack by content ID. A missing amount represents one unit. Invalid amounts stay unavailable. Consumable classification uses scroll IDs and item metadata, including potion and ammunition types. Stackability and charges alone do not make a reusable item consumable.

Using a consumable subtracts one unit from the active stack and disables further use at zero. The Rust session keeps the usage record when Aurora content changes or the save is re-imported. The standalone preview records the same per-stack usage in browser storage and updates every visible copy, including pins. Re-import supplies the new starting quantities and the tracker continues to subtract the units already recorded. The Aurora files are read-only.
