# User requirements

A personal Windows app that uses an Aurora character and its content to show combat options and track the encounter.

R31–R54 cover multiplayer. For implementation entry points and regression checks, see the [multiplayer UI handoff](multiplayer-ui.md).

| ID | Requirement |
| --- | --- |
| R1 | Import a `.dnd5e` save and resolve entries against the same Aurora content, including custom XML. Load available combat stats, attacks, spells, features, and inventory. Flag missing details and allow manual corrections. Treat source files as read-only. |
| R2 | Use the spell, item, feature, and companion definitions referenced by the character for version-specific rules and options. |
| R3 | Refresh through the Windows launcher using the original Aurora inputs. Preview unresolved definitions, unavailable stats, definition sources, and significant changes before applying a refresh. Preserve the previous sheet and tracker progress when an import fails. |
| R4 | Group attacks, spells, scrolls, items, and features by Action, Bonus Action, or Reaction. Keep the groups available for reference throughout the turn. Show relevant costs, ranges, rolls, and save DCs with full descriptions that expand in place. |
| R5 | Keep HP, AC, speed, and saves easy to find. Allow per-character pins, reordering, and hidden sections. Keep lore, personality, and background available in the full sheet. |
| R6 | Record consumable use immediately. When re-import changes a stack with pending usage, show both imported quantities and let the player reconcile units already reflected in Aurora. Preserve stack identity and encounter progress. |
| R7 | Show active concentration and its tracked duration. Prompt for a concentration save when recorded damage calls for one, let the user record the result, and confirm before replacing an active concentration spell. |
| R8 | Support pets, familiars, summons, constructs, and other companions through editable cards. Share availability with initiative and action controls. An Eldritch Cannon vanishes at zero HP or on expiration. Other companions have a configurable zero-HP rule. Advance summon timers in their chosen units and restore HP and availability together on undo. |
| R9 | Keep round, current turn, initiative, and Next Turn accessible from the encounter panel. Let the user end or restart an encounter while preserving character state and ongoing effects. Save progress locally and allow undo for turn advances, ending an encounter, resource spending, HP, effect changes, and other combat updates. |
| R10 | Track conditions and ongoing effects with notes and expiration rules. Support rounds, game time, turn boundaries, rests, and manual expiration. When a participant is removed, end its target effects and allow turn-anchored effects on other participants to end or move to another turn in the same undoable update. |
| R11 | Pin actions to a collapsible Quick Actions strip for direct execution, independently of Favorites. Preserve cannon creation and activation shortcuts. Share resource, availability, and companion state with the other combat views. |
| R12 | Keep character vitals, resources, concentration, companions, and effects accessible while browsing Character, Inventory, and the combined Journal and Notes page. Preserve navigation state and combat activity between views and after reopening a sheet. Keep the desktop panes usable at 1920×1080 and 2560×1440 at 100% and 125% scaling. |
| R13 | Let the user search skills, saves, ability checks, casts, attacks, and supported tool and initiative bonuses from the character header. Show passive scores and break down modifiers wherever the imported data supports it. |
| R14 | Let the user expand tracked abilities to read custom descriptions or link to existing spells, features, items, and ongoing effects. Preserve saved ability states, usage, and resource bindings. |
| R15 | Show skills, saves, and passive scores directly on Character. Let players dock skills in Combat and search the entire sheet without changing the current page. Keep senses, languages, tools, movement, and background features easy to find. |
| R16 | Let players organize Features & Traits into named groups and set their own order. Show timing, triggers, costs, and rest recovery separately. Track shared class pools such as Moxie alongside individual uses and let the player record outcomes. |
| R17 | Link imported gear and saved attacks where the association is clear. Allow local notes and corrections to the association. |
| R18 | Show and edit currency in Inventory. Persist pending balances across reloads. Export an Aurora `.dnd5e` copy with updated balances and the original character data. |
| R19 | Export a versioned tracker backup and validate and preview it before replacing the current session. Restore in another browser profile or against a moved or exported Aurora save. Include encounter state, preferences, notes, and local corrections. |
| R20 | Offer a persistent Compact Combat layout with vitals and pinned resources, an initiative summary, direct owner healing and combatant HP adjustments, stable keyboard focus, and search that includes active follow-ups. |
| R21 | Activate reusable charged items from a bound pool and show remaining uses. Distinguish slot, ritual, and free-use casting and commit applicable costs together with concentration. Filter Inventory, reorder custom feature groups, and open Table notes from either side of an attack and gear link. |
| R22 | Keep a persistent undo-aware encounter activity log for combat updates and zero-cost casts. Save reusable rosters and effect presets and archive encounters for later review. |
| R23 | Optionally track Action, Bonus Action, and Reaction for the owner and companions. Share availability across execution controls and allow a per-use override for table rulings. |
| R24 | Add dated, searchable Journal entries linked to encounter activity or sheet references. Preserve existing journal and notes text. |
| R25 | Show current cantrip dice and separate attacks when the resolved spell text identifies how they scale with character level. Preview supported damage, healing, and projectile counts for the selected spell slot. Leave ambiguous effects available as rules text. |
| R26 | Resolve supported Aurora class-stat formulas using the saved class levels and ability modifiers. Show the resulting dice, uses, save DCs, and shared pools. Let features spend stated costs or select an amount for a variable healing pool. |
| R27 | Track numbered strikes in the same Attack action when the character has Extra Attack. Record hit or miss and let the player apply eligible Sneak Attack and on-hit maneuvers. |
| R28 | Show authored reaction triggers and offer matching, available spell reactions while recording incoming attack or Magic Missile damage. Let the player apply situational attack modifiers when the imported spell states a supported condition. |
| R29 | Filter the character's spells by preparation, school, ritual, concentration, and material cost. Show costly or consumed materials during casting. Preview supported target-count upcasts, link supported spell effects to their targets and concentration, and show turn reminders for tracked creatures in an area. |
| R30 | Show attunement requirements and let the player record which items they have attuned to. Gate supported item activations on the saved selection. Restore charges from supported dawn formulas when the player advances to dawn. |
| R31 | Keep party members distinct even when they use the same name. A player can resume their membership after a disconnect. Only an offer's sender and recipient see its mechanics and outcome. The recipient can claim and then accept or decline, or decline before claiming. Withdrawal, expiry, and room closure preserve an existing HP claim so its recipient can finish after a restart. |
| R32 | Host a party from the Windows launcher on a selected IPv4 adapter, host a DM lobby without a character, or join a pasted invitation. Show member names, presence and reconnect status under Session → Party. Hosts can copy, replace or close invitations and end the room. Guests can leave. Resume a saved membership after a helper restart. Standalone sheets support solo play. |
| R33 | Send healing or temporary HP to a party member from Session → Party. Enter the amount and source, then track the recipient's acceptance or decline. The recipient applies healing up to their maximum and keeps the higher temporary HP. The recipient can undo the local HP change without making the offer eligible for delivery again. Restoring a backup detaches the sheet and lets the player reconcile a claimed offer after resuming. |
| R34 | Choose local companions, yourself, or party players from a healing cast, a variable healing pool, or Protector in Combat and Quick Actions. Enter rolled HP once or choose the points to spend. The action spends its cost once. Each remote target receives a separate offer and can decline independently. |
| R35 | Assign an active attack infusion or custom imbuement to a party player. The recipient privately chooses one eligible weapon or spell attack. Ending, replacing, or expiring the source ends its grant, including when a player reconnects. The sender sees the offer and its status. |
| R36 | Host as DM from the Windows picker to open a standalone dashboard without an Aurora save or XML library. The party overview shows each player's presence and shared vitals. Hide AC in the overview while keeping shared AC visible in the read-only inspector. Stale values are marked while a player is offline. |
| R37 | Choose Party name only, Vitals, or Character details under Session → Party for the current DM room. New memberships start at name only. Vitals shows effective HP, temporary HP, AC, initiative, conditions and concentration. Character details also shows ability scores, saves, skills, attacks, spells, features, inventory, and remaining resources. Downgrading removes withdrawn data from the DM view and closes an open inspector when access returns to name only. |
| R38 | In Host as DM, add, edit, duplicate, reveal, hide and remove individual enemies. Track each enemy’s private name, public alias, current and maximum HP, AC, conditions, initiative and action notes. Enter or roll initiative, give matching enemies the same score and break ties. Players see the revealed alias or “DM turn.” |
| R39 | In a DM room, submit initiative from Combat → Initiative. A companion can share its owner’s turn or take a separate initiative score. The DM starts, advances, corrects and ends the encounter and can save or resume a named roster and turn position. Leaving restores the player’s solo initiative. |
| R40 | Apply owner and companion turn boundaries once, including after disconnection or host restart. A round advances game time by six seconds. The DM can also advance time explicitly. Correct current turn moves the pointer. Each owner can restore their last clock outcomes on their sheet and use the existing editors for individual adjustments. |
| R41 | Open Monster library from the DM dashboard to search a pack and filter by creature type, size and challenge rating. Pack choices identify source and rules edition. Mixed-size creatures match each recorded size. Preview complete stat blocks and add multiple independent enemies on a shared initiative score. When available, the printed score prefills the editable initiative field. Each enemy keeps its own HP, stable row ID, and the stat block from the template revision used to create it. Named rosters preserve these records across host restarts. |
| R42 | Create and edit local monster templates and import and export native JSON packs in versions 1 and 2. Review pack details before replacing a matching ID. Invalid files and stale replacement previews leave the installed revision intact. Load creature-shaped Aurora Companion definitions and linked rules from a selected local XML folder. Show unresolved links and formulas in the stat block. |
| R43 | Show each template's recorded source version, entry location, license, and attribution. Preserve fractional challenge ratings, printed initiative, qualified defenses, gear, legendary action rules, and additional rules sections. Distinguish unknown values from zero and show conditional AC separately from base AC. Keep complete rules text available alongside any structured damage, saves, uses, recharge, legendary costs, and ordered strikes. |
| R44 | Include the English Creative Commons SRD 5.1 monster and NPC stat blocks as the default 2014 pack in Host as DM → Monster library. Search, preview, and add entries offline. Keep the printed rule text available for table adjudication, including conditional effects, recharge, and legendary costs. Show source pages and Pack credits offline, and retain attribution and the license reference in JSON exports and the Windows package. |
| R45 | Include the English Creative Commons SRD 5.2.1 monsters and animals as an offline 2024 pack alongside 2014. Identify the edition in search results, stat blocks, and DM initiative so same-name creatures can share an encounter. Preserve printed initiative, alternative sizes, gear, riders, and lair qualifications. Show each pack's source and credits offline, and retain each enemy's edition and stat block after a library replacement. |
| R46 | In Host as DM, use Monster actions beside initiative to read the current enemy's rules, add a hand-entered action, and record a manual ruling. Record an optional physical roll total, hit, miss or save outcome and target for each strike, plus a private note or override. A canceled preview spends nothing. Committing multiple strikes spends the parent action once. Keep action history, private targets and raw totals on the DM dashboard so the DM can decide what to say at the table. |
| R47 | Track action, bonus action, reaction, legendary uses, power uses and recharge separately for each enemy. Queue a physical recharge roll for that enemy's next real turn start. Apply supported power resets on their configured boundaries and use the correction controls for rests, table rulings or text-only mechanics. Saving and loading restores recorded actions and counters. Correcting the turn pointer leaves costs and queued rolls intact. Duplicate copies the current counters and creates an independent enemy with empty action history and no queued roll. Add to encounter creates fresh counters for every copy. |
| R48 | From a recorded monster strike in Host as DM, enter one final damage amount for its player target or mark the result handled at the table. A miss or zero closes without an offer. Two strikes against the same player can each send an offer. Track its status and request a correction through Damage offers. Private monster names, rolls and rulings stay on the DM dashboard. |
| R49 | Accept or decline DM damage in Session → Party, including at name-only sharing. Acceptance applies damage to your sheet once, uses temporary HP first, and handles concentration, zero HP and the activity log as local damage does. If HP is unavailable, set it before accepting. Undo or correct damage on your own sheet. After restoring a backup, reconcile outstanding claims by applying them, marking them already handled, or declining. |
| R50 | Send an optional save or reaction question from a recorded strike in Host as DM. The target can answer hit, miss, save success, save failure, or pass in Session → Party at name-only sharing. Use an available Shield reaction and choose the table outcome in the same reply. Keep defenses, slots and spell details on the owner's sheet. Only text the DM explicitly enters as a public announcement appears to the party. |
| R51 | Continue initiative and other strikes while a question waits. Save questions can wait for a reconnect. A pending reaction trigger becomes stale on turn advance. The DM can use a reply, cancel or replace a question, or enter a spoken ruling with a private override reason before resolving damage. Late replies leave closed questions closed. The owner can correct a reaction spent before a late reply was rejected. |
| R52 | Start monster action previews in Manual or opt into Assist. Choose digital attack rolls, armor class comparison and damage suggestions independently for each strike. Store a natural d20 separately from an entered or computed total. Use an online player's currently shared armor class or an unqualified enemy armor class for attack suggestions, and make the ruling at the table when it is unavailable. Switch modes or review an unresolved strike without paying the parent action cost again. |
| R53 | Review printed save branches and conditional riders in Assist. Use rolled, printed-average or custom damage and confirm any resistance or other modifier before using a suggestion. Resolve each target separately and confirm the final amount through the existing damage offer. Saved rolls and replies carry forward through retries and mode switches. |
| R54 | Show the DM dashboard as one screen at 1920×1080: room status and invitation controls in a top bar, a visual turn order with the current turn, HP bars and hidden or revealed state, the selected combatant with its actions and stat block, and party cards with HP, AC, conditions and concentration. Keep the labelled turn-order list for keyboard use. On the player sheet, show a Party chip in the header with the connection state and the number of DM questions and offers waiting for an answer. |
| R55 | Give the solo sheet the same visual language as the DM dashboard without changing its layout or control names: icons on the main navigation and vital cards, an HP card whose colour and bottom meter follow current HP, serif panel headings, and distinct Attack, Cast and Next Turn buttons. |

## First playtest

1. Import an Artillerist whose Aurora content provides Force Ballista, Flamethrower, and Protector. Verify that all three variants show the imported details.
2. Add a ranger companion using the same companion system.
3. Apply a timed effect, advance initiative until it expires, and undo the update to restore it.
4. Use a scroll from its action group and record damage while concentrating. Verify the quantity and concentration prompt, then close and reopen the app to verify the encounter resumes.
