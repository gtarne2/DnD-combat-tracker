# User requirements

A personal Windows app that uses an Aurora character and its content to show combat options and track the encounter.

R31–R54 cover multiplayer. For implementation entry points and regression checks, see the [multiplayer UI handoff](multiplayer-ui.md).

| ID | Requirement |

| R40 | Apply owner and companion turn boundaries once, including after disconnection or host restart. A round advances game time by six seconds. The DM can also advance time explicitly. | R41 | Open Monster library from the DM dashboard to search a pack and filter by creature type, size and challenge rating. Pack choices identify source and rules edition. Named rosters preserve these records across host restarts. |
| R42 | Create and edit local monster templates and import and export native JSON packs in versions 1 and 2. Review pack details before replacing a matching ID. Show unresolved links and formulas in the stat block. The DM can pick several files or a whole folder (only `bestiary*.json` when the folder has them; lore, index and other lists are passed over) and reviews them together. The launcher's first screen lists bestiary files and folders, remembered between runs, that a DM room loads into the library when it starts, skipping books that have not changed; the monster library reports what loaded. Skipped `_copy` records are listed in the import review, and the monsters join encounters like bundled templates. |

## First playtest

1. Import an Artillerist whose Aurora content provides Force Ballista, Flamethrower, and Protector. Verify that all three variants show the imported details.
2. Add a ranger companion using the same companion system.
3. Apply a timed effect, advance initiative until it expires, and undo the update to restore it.
4. Use a scroll from its action group and record damage while concentrating. Verify the quantity and concentration prompt, then close and reopen the app to verify the encounter resumes.
